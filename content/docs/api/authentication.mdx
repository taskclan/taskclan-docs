## Cloud API keys

The Cloud API is authorized with an `sk_cloud_…` **API key**, issued from the
console. A key resolves to an organization and carries its scopes, so org access
and RBAC stay server-side.

```bash
curl https://engine.taskclan.com/api/cloud/v1/sites \
  -H "authorization: Bearer $TASKCLAN_CLOUD_API_KEY"
```

<Callout type="warn">
  An `sk_cloud_…` key is org-wide and long-lived. Keep it on servers and in CI
  secrets only — never in a browser bundle or a public repo.
</Callout>

## User access tokens

Interactive, user-scoped calls use short-lived access tokens (they expire in
about an hour). Prefer an API key for anything that must keep working
unattended — a dashboard that stops working an hour after setup is worse than one
that never started.

## Never expose

The database **service-role** key and any provider secrets are never returned by
the console or the API for client use. Surface the anon key on clients and the
connection string on servers.
